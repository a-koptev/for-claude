# FeatureZoneModule

Модуль собирает Re-ID gallery для локальных треков, когда контрольная точка bbox попадает в полигон зоны. Использует `FeaturesManager.extract_features(image_list)` и `calculate_similarity(...)`.

## Схема зон

Все координаты размечаются на кадре 1280x720. Полигоны задаются в `feature_zones.yaml`; пустой список означает, что зона выключена.

- **Камера 1:** две зоны `LEFT` и `RIGHT`. Проверяется нижняя центральная точка bbox. Зона определяет, у какого шлагбаума появился трек.
- **Камера 2:** две зоны `LEFT` и `RIGHT`. Проверяется центр правой грани bbox. Сторона определяется по зоне, в которую попала эта точка.
- **Камера 3:** одна зона `DEFAULT`. Проверяется центр верхней грани bbox.
- **Камеры 4–9:** одна зона `DEFAULT`. Проверяется нижняя центральная точка bbox; логика не зависит от стороны въезда.

На камерах 1 и 2 обе зоны проверяются автоматически, не нужно заранее переключать активную сторону для обработки. Переключение `1`/`2` в отладчике выбирает только зону, которую редактируют.

## Захват признаков

- Каждые N кадров все треки с контрольной точкой внутри подходящей зоны проверяются для съёма.
- Кропы подходящих треков и горизонтальные отражения отправляются в одном batch-вызове экстрактора.
- Сравнивается только новый ORIGINAL embedding с последним принятым ORIGINAL. Если cosine similarity >= 0.90, пара отклоняется как почти дубликат; иначе original и flip добавляются в разные массивы.
- Вектора L2-нормализуются. Галереи разделены по `(camera_id, local_track_id)`; у галереи сохраняется `zone_profile`.

### Если локальный track_id поменялся

Зона проверяется по каждому текущему bbox независимо от того, был ли такой track_id раньше. Поэтому новый ID, появившийся внутри зоны, тоже начнёт собирать признаки. Однако это будет отдельная локальная галерея: модуль намеренно не объединяет автоматически два ID только из-за близости во времени/пространстве — такое объединение может склеить соседние машины. Сопоставление и возможное объединение галерей нужно делать отдельным этапом по Re-ID и контексту трека.

## Жизненный цикл

При событии EXIT вызывающий код может закрыть галерею через `end_tracks_on_exit(camera_id, events)`. На остановке потока — `close_all()`. Сам модуль не пишет в БД.

Пример:

    from FeatureZoneModule import FeatureZoneManager
    from FeaturesModule.FeaturesManager import FeaturesManager
    from Config import Config

    features = FeaturesManager(Config.OSNET_MODEL_PATH)
    zones = FeatureZoneManager(features, "feature_zones.yaml")
    accepted = zones.process_frame(
        camera_id=2,
        frame_id=frame_id,
        frame=frame,
        tracks=list(zip(track_ids, boxes)),
    )

## Запуск отладчика из PyCharm

Откройте и запустите зелёной кнопкой Run файл
[`run_feature_zone_debug.py`](https://github.com/a-koptev/for-claude/blob/feature-zone/run_feature_zone_debug.py).
Аргументы командной строки не нужны. Если `VIDEO_SOURCE` не найден, появится диалог выбора видео. Скрипт не подключается к БД.

### Клавиши

- **E** — включить/выключить рисование полигона; щёлкайте по углам области по порядку.
- **1 / 2** — выбрать зону LEFT / RIGHT на камерах 1 и 2.
- **D** — выбрать DEFAULT на камерах 3–9.
- **S** — сохранить `feature_zones.yaml`.
- **C** — очистить выбранный полигон.
- **Space** — пауза; **Q** или **Esc** — выход.

Для новой разметки: выберите номер камеры в блоке SETTINGS в начале скрипта, запустите видео, выберите профиль, нажмите E, поставьте углы области и нажмите S. Для камеры 1 и камеры 2 повторите действия для второй стороны.

Отладчик показывает bbox и контрольную точку: камера 2 — центр правой грани, камера 3 — центр верхней грани, остальные — нижняя середина. Линии переходов из topology.yaml, если включены, относятся к переходам между камерами и не являются зонами захвата.

Логи: `feature_zone_debug.log`; сводка: `feature_zone_debug_report.json`.

## Проверки

Запустить `python -m unittest discover -s tests -p test_feature_zone.py`. Тесты используют fake extractor и не требуют весов OSNet. Нужны OpenCV, NumPy и PyYAML.
