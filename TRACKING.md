# Tracking и переходы между камерами

## Текущий режим тестирования

`Tracking.py` может работать без Re-ID:

```python
USE_TRACKLET_MANAGER = False
```

Используются YOLO, BoT-SORT, `CameraNetwork` и `CrossingDetector`.

## Поток обработки кадра

1. видео приводится к `1280x720`;
2. исходный кадр передаётся в YOLO/BoT-SORT;
3. из bbox вычисляются центры;
4. `CrossingDetector` проверяет пересечение линий центрами треков;
5. при переходе создаётся `TransitionEvent`;
6. событие пишется в консоль и `transitions.log`;
7. линии и bbox рисуются только на отдельной копии кадра.

## Условие перехода

Переход считается только при смене стороны линии центром bbox.

Если bbox касается линии, но центр ещё находится по другую сторону, переход не фиксируется. Если YOLO впервые дал bbox уже после линии, детектор анализирует движение центра и заднюю грань bbox. При выступании задней грани не более чем на 10 px переход всё ещё принимается; если автомобиль полностью ушёл дальше этого допуска, позднее событие отбрасывается.

Если центр перескочил через линию между двумя последовательными кадрами, дополнительно проверяется пересечение конечного отрезка линии, а не его бесконечного продолжения.

## Направление

Направление берётся из смещения центра:

```
motion = current_center - previous_center
```

`TransitionLine.role_of_motion()` сравнивает движение с настроенным `exit`: направление `exit` даёт `EXIT`, обратное — `ENTER`.

Движение почти вдоль линии отбрасывается по `MIN_MOTION_ALIGNMENT`.

## Защита от повторов

После события для `track_id + line_id` устанавливается блокировка. Она снимается после того, как центр находится не ближе `TRANSITION_RELEASE_MARGIN_PX` к линии в течение `TRANSITION_RELEASE_FRAMES` кадров.

## Маршрут

`Tracking.py` ведёт локальный маршрут, например `[1, 9, 8]`.

Одинаковый числовой BoT-SORT ID на двух разных камерах не считается одним автомобилем. Межкамерное объединение ID будет выполняться отдельным слоем Re-ID.

## Следующий этап

После стабилизации геометрии переходов:

1. получать событие `camera A -> camera B`;
2. ограничивать кандидатов Re-ID камерой B;
3. учитывать временное окно между выходом с A и появлением на B;
4. объединять локальные track ID в единый ID автомобиля;
5. при необходимости разрешать перенос или перепривязку ID.
